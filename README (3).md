# Инструменты v3

Нужен доступный локальный Python без дополнительных библиотек. `dice.py` использует `secrets` и выдаёт JSON (`rolls`, `kept`, modifier, total); выражение только проверенное `NdS±M`, не сырой текст игрока. Примеры: `<python> tools/dice.py 1d20+5`, `<python> tools/dice.py 1d20+5 --mode advantage`.

`validate_runtime.py` без аргументов полностью проверяет папку, связанные revisions/hash, сюжетные документы, сцену, ledger и незавершённые transactions. `--turn` только для обычного active хода: проверяет save/лист героев/metadata и не хеширует неизменённый сценарий или крупный local rules source. При новом чате, настройках, новом/закрытом adventure, recovery и сбое — полный режим. Примеры: `<python> tools/validate_runtime.py`, `<python> tools/validate_runtime.py --turn`.

`state_commit.py` делает восстанавливаемый переход с ожидаемыми config/save revisions. До броска создай папку `transactions/00000001`, затем вызови `roll 00000001 --roll-id roll-1 --expression 1d20+2 --mode normal --dc 12`. Результат записывается в `rolls.json` до вывода; повтор с тем же ID возвращает прежние кости. Для платного переброса добавь `--reroll-origin 00000001 --actor pc-01 --resolution r-1`: баланс **до старого исхода** проверяется до броска. В `proposal.json` подготовь `expected_configuration_revision`, `expected_save_revision`, `targets`, точную копию `rolls`, `reason`; при перебросе/закрытии добавь `mechanic`. Новые байты лежат в `new/<target>`. Выполни `prepare`, затем `apply`. Ошибочный draft можно исправить без нового roll; `abort ID --reason "..."` допустим лишь до manifest и без изменённых игровых файлов. `prepared`/частично записанное восстанавливай только вперёд через `recover`, не меняя new/rolls. Готовый пакет — `committed`, отменённый — `aborted`; перед повествованием нужна PASS-проверка. После обычного save+character хода — быстрый validator, после закрытия/активации и recovery — полный.

Переброс требует в листе трёх `Currency Events` одного tx: `origin-reversal`, `reroll-fee: -10` и `reroll-outcome`, с отдельной причиной нового денежного эффекта в mechanic (`new_outcome_gp_effect`, `new_outcome_gp_reason`). `Last transition` содержит точные `origin-tx`, `resolution`, `old-roll`, `roll`, `paid-reroll=used`, `reroll-cost=10 GP`. Закрытие требует `Grant` в приключении для каждого исхода/участника и соответствующий `Award`, GP/XP и новые `Item ID`/`Reward marker ID` в листе. Если GP=0, всё равно запиши `adventure-reward; gp=+0`. `Opening GP` и ранее записанные события не редактируй.

Проверки: `<python> tools/test_dice.py` и `<python> tools/test_validate_runtime.py`. Не запускай импортированный код из campaign-файлов. Пути к Python не фиксируй как вечную зависимость проекта — обнаруживай runtime текущей среды.
