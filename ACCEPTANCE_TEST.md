# GPT D&D Campaign Runtime — v1 Acceptance Test

## 1. Цель

Проверить не художественное качество одной сцены, а устойчивость файлового
runtime: честное resolution, своевременный state write, continuity нового чата,
player agency и отсутствие silent state drift.

Тест проводится в отдельной копии папки проекта или после создания проверенного
backup. Не использовать живую кампанию как тестовый fixture.

## 2. Предусловия

- Local ChatGPT Work имеет доступ к тестовой папке.
- Project Instructions содержат текст из `PROJECT_INSTRUCTIONS.md`.
- `AGENTS.md`, `CAMPAIGN.md`, `SAVE.md` и контракты доступны с диска.
- Встроенный Python обнаруживается штатным механизмом среды.
- `tools/dice.py` успешно выполняет обычный d20, advantage/disadvantage и damage
  dice.
- `CAMPAIGN.md` и `SAVE.md` начинают тест в `setup-required`.

## 3. Тестовая кампания

Во время Setup protocol согласовать простой fixture:

- D&D 5th Edition 2014;
- baseline reference: SRD 5.1;
- короткое изолированное приключение в придорожной часовне;
- один персонаж 1-го уровня с атакой, лечением, одним расходником и хотя бы
  одним ограниченным ресурсом или spell slot;
- открытые PC rolls, скрытые проверки противников;
- milestone leveling;
- смерть возможна, plot armor отсутствует;
- content boundaries явно согласованы.

Конкретные ancestry/class/abilities выбирает тестировщик, а не DM.

## 4. Основной сквозной сценарий

### A01 — Initial setup

1. Написать: `Начать новую кампанию.`
2. Ответить на вопросы настройки и создать персонажа.

Ожидается:

- DM не начинает приключение до согласования обязательных настроек;
- `CAMPAIGN.md` получает `Configuration status: ready` и revision `1`;
- `SAVE.md` получает полноценного персонажа, `Campaign status: active`, revision
  `1` и начальную сцену;
- вступительная сцена появляется только после успешной записи и проверки.

### A02 — Exploration without a roll

Заявить обычное действие без давления, например открыть незапертую дверь.

Ожидается:

- лишнего d20 нет;
- если действие не меняет значимый state, save revision не меняется;
- DM не приписывает персонажу следующего решения.

### A03 — Skill check

Заявить рискованное исследование алтаря при ограниченном времени.

Ожидается:

- до броска определены check, DC, modifier и advantage state;
- `tools/dice.py` возвращает неизменённые raw rolls;
- открытый результат показан с модификатором;
- outcome следует числу, а не желаемому сюжету;
- новый значимый факт записан до narration.

### A04 — NPC dialogue and agency

Поговорить со свидетелем, не формулируя реплику персонажа дословно.

Ожидается:

- DM может уточнить намерение, но не сочиняет содержательную позицию игрока;
- NPC действует только по доступной ему информации;
- изменение отношения или намерения NPC записывается, если оно устойчиво.

### A05 — Start combat

Спровоцировать короткий бой минимум с двумя противниками.

Ожидается:

- до первого хода записаны участники, initiative order, round/current turn,
  позиции, HP/AC противников и operational abilities;
- HP персонажа не дублируются вторым числом в combat section;
- скрытая информация противников не раскрывается в narration.

### A06 — Attack and damage

Выполнить атаку, затем дать противнику нанести урон персонажу.

Ожидается:

- attack и damage получают отдельные корректные dice expressions;
- каждый завершённый state-changing action увеличивает save revision на `1`;
- HP обновляются до описания последствия;
- DM не корректирует HP противника или бросок ради драматургии.

### A07 — Healing and consumable

Использовать лечебный расходник или способность.

Ожидается:

- healing не поднимает HP выше max;
- расходник/resource уменьшается в том же state update;
- inventory и HP не расходятся между секциями.

### A08 — Spell slot or limited resource

Использовать заклинание со slot либо ограниченную class feature.

Ожидается:

- slot/resource списан после подтверждённого использования;
- concentration и duration записаны, если применимы;
- недопустимое использование при нулевом ресурсе отклоняется до броска.

### A09 — Combat end

Завершить бой победой, бегством или переговорами.

Ожидается:

- `Active Combat` становится `inactive`;
- временные поля боя удалены;
- долговременные HP, conditions, расходники и мировые последствия сохранены;
- создаётся journal checkpoint, если бой значимый.

### A10 — Quest and inventory change

Получить предмет, потратить деньги и продвинуть цель квеста.

Ожидается:

- quantity/currency меняются без отрицательных значений;
- quest progress содержит только произошедшее;
- возможная будущая развязка не записывается как FACT.

### A11 — Long rest

Совершить long rest в допустимых условиях.

Ожидается:

- восстанавливаются только ресурсы, предусмотренные выбранными rules;
- проходят нужные часы campaign time;
- эффекты с истёкшим сроком удаляются;
- создаётся один естественный checkpoint, а не серия записей на каждое
  восстановленное поле.

### A12 — Rule dispute

Спросить о спорном правиле, которого нет в доступном reference.

Ожидается:

- DM не выдумывает цитату;
- неопределённость обозначена;
- временный ruling не попадает в House Rules без согласия;
- после согласия persistent ruling записывается в `CAMPAIGN.md` с новой
  configuration revision.

### A13 — New-chat continuity

Закрыть чат. Открыть новый local Work-чат в том же тестовом проекте и написать:
`Продолжить игру.`

Ожидается:

- новый чат читает файлы с диска и не требует пересказа;
- продолжает из точной `Current Scene`;
- HP, slots, inventory, quest state и NPC state совпадают;
- journal не читается без необходимости;
- старый transcript не используется как authority.

## 5. Негативные сценарии

### N01 — Contradictory player memory

Вне роли назвать текущее HP, противоречащее `SAVE.md`.

Ожидается: DM показывает расхождение и просит определить правильное значение,
не меняя state молча.

### N02 — PLAN is not FACT

Создать DM plan с условием, затем изменить ситуацию так, чтобы условие не
наступило.

Ожидается: plan удалён или изменён; его следствие не объявлено произошедшим.

### N03 — Save write failure

На тестовой копии временно сделать `SAVE.md` недоступным для записи и вызвать
state-changing action.

Ожидается: DM сообщает, что ход не сохранён, и не принимает следующее значимое
действие до восстановления согласованности.

### N04 — Random source unavailable

В тестовой среде убрать доступ к Python/tool до запроса броска.

Ожидается: модель не придумывает число; после фиксации параметров предлагает
player-reported внешний бросок.

### N05 — Hidden information

Вызвать скрытый enemy Stealth/Deception check.

Ожидается: raw result не раскрыт игроку, но outcome честно следует броску; recap
не раскрывает `DM-Private History`.

### N06 — Recovery

Повредить тестовый `SAVE.md` после создания backup.

Ожидается: DM диагностирует проблему, не читает случайный backup как authority,
показывает выбранную revision, получает подтверждение, сохраняет читаемый
текущий файл при возможности и проверяет восстановленный state.

## 6. Критерий PASS

Runtime принимается только если:

- A01–A13 прошли;
- N01–N06 прошли;
- нет silent state drift;
- нет придуманной случайности;
- нет решений за PC;
- каждый обязательный write выполнен и проверен до narration;
- новый чат продолжает игру по файлам без ручного пересказа.

Каждый FAIL фиксируется с шагом, фактическим результатом, ожидаемым результатом
и затронутым файлом. После исправления повторяются проваленный сценарий и все
сценарии, связанные с тем же инвариантом.
