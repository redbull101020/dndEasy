# Backup Contract — v1

## 1. Назначение

`backups/` хранит recovery-копии `SAVE.md`. Backup не является текущим state,
не участвует в обычном startup и не используется для выбора более удобной
версии событий.

## 2. Имена

- Последовательные имена: `save_0001.md`, `save_0002.md` и далее.
- Перед созданием выбирается следующий свободный номер непосредственно по
  содержимому папки.
- Существующая копия никогда не перезаписывается.
- Внутри копии уже находятся `Save revision` и `Updated at`, поэтому отдельный
  manifest для v1 не нужен.

## 3. Когда создавать backup

Обязательно:

- перед level-up или пересчётом большей части character sheet;
- перед массовым импортом или структурной миграцией `SAVE.md`;
- перед согласованным исправлением нескольких связанных state-секций;
- перед восстановлением из старого backup, если текущий файл ещё читается;
- по явной просьбе игрока.

Рекомендуется:

- после крупного сюжетного checkpoint;
- в конце насыщенной сессии с большим числом долговременных изменений.

Не создавай backup после каждого хода или обычного одиночного state write.

## 4. Создание и проверка

1. Убедись, что текущий `SAVE.md` читается и прошёл базовые инварианты.
2. Выбери следующий свободный номер.
3. Создай точную копию текущего `SAVE.md` без изменения её содержимого.
4. Перечитай копию и сравни её размер и SHA-256 с текущим `SAVE.md`.
5. Только после совпадения считай backup успешным.

Создание backup само по себе не меняет игровой state, поэтому не увеличивает
`Save revision`.

## 5. Восстановление

Восстановление — явная recovery-операция, а не обычное действие DM.

1. Определи точный backup и проверь, что путь остаётся внутри `backups/`.
2. Прочитай его полностью и проверь формат и основные инварианты.
3. Покажи игроку, какая revision восстанавливается и какие более новые данные
   могут быть потеряны.
4. Получи явное подтверждение игрока.
5. Если текущий `SAVE.md` читается, сначала сохрани его следующим свободным
   backup-файлом и проверь копию.
6. Восстанови выбранное содержимое в `SAVE.md`.
7. Установи новую `Save revision` на единицу больше максимальной revision
   текущего файла до восстановления и выбранного backup.
8. Обнови `Updated at` и добавь краткую временную запись о recovery в
   `Operational Notes`.
9. Перечитай итоговый `SAVE.md` и проверь инварианты.

Нельзя молча восстанавливать backup только потому, что он выглядит более
правдоподобно, чем текущий state.

## 6. Хранение

- Не удаляй и не сокращай backups автоматически.
- Не редактируй backup после создания.
- Не считай наличие backup доказательством текущего факта.
- Политику очистки можно добавить позднее только при реальной проблеме размера.
